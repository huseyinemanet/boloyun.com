## What the evidence establishes

Supabase plugin lists `boloyun` (`yjoipnnyhpgvzukhrljp`) as INACTIVE. A minimal
read-only SQL request timed out. The dashboard required sign-in, so 10.93 GB
organization usage and the claimed 3.6 GB September 11 amount remain
user-provided values, not independently verified project totals.

SSH verified the live image is the repository baseline. `/opt/boloyun/cache`
is mounted read/write at `/app/.next/cache`, owned by UID 1001, and occupied
about 2.9 GiB. The retained fetch-cache files include tens of thousands of
`games`, `games|categories|tags`, and `comments` entries. This disproves the
assumption that production has no persistent Data Cache. Disk bytes are not
network egress. Cache entries can contain historical or failure/empty values.

The worker retained its September 10–11 logs. The first retained quota failure
was `2026-09-11T22:27:59.831653044Z`, explicitly `exceed_egress_quota`.
Two daily AI-history maintenance events were retained, one each day. No retained
bulk-import event proves a job-driven spike. The web container restarted on
September 18, so its September 11 query logs were unavailable. Worker is currently
unhealthy while the web process is healthy; the public root still returned 200.
A healthy process or cached HTTP 200 does not establish database availability.

Supabase egress; without historical Supabase path/byte logs that equation cannot
be solved precisely.

## Changes prepared

- All 15 `.select("*")` occurrences replaced with explicit projections; AST
  regression test prevents wildcard or implicit full-row selects returning.
  Import queue now selects nine list fields and caps pages at 100; raw source
  HTML is not downloaded for review lists or normal import detail/workflow reads.
- Game metadata, page snapshots and related results use 12-hour Data Cache TTL.
  Existing admin content tags still invalidate them. Successful missing-game RPCs
  do not trigger another lookup; DB failures do not become cached game fallbacks.
- Related candidate pools share cache keys across equal taxonomy sets and return
  at most 251 rows each (250 after excluding the current game), down from 1,000
  each. Only the configured recommendation strategy is fetched; the other two
  no longer add unused payload. Each strategy now returns at most 12 cards (up to 72 ranked candidate cards
  instead of 150).
- Archive has a one-hour cache; search results have a five-minute cache and a
  minimum of three characters. Sizes/pages are finite and bounded before cache
  key construction. Categories/tags cap public page size at 48; search caps at 24.
  Search normalization preserves letter case to avoid changing DB collation.
- Search API no longer calls Supabase just to check its rate limit on every hit.
  It uses a bounded 90/min process backstop plus the prepared Nginx perimeter
  limit. Auth and mutation rate limits are unchanged. The process backstop resets
  on restart and is not a multi-replica distributed limiter.
- Sitemap records/counts have a 24-hour Data Cache independent of route caching.
  This matters because the dynamic game sitemap handler did not get a full
  route cache merely from exporting `revalidate`. Tag counts now use the existing
  aggregate RPC instead of downloading relationships (which could also truncate
  counts at the API row cap). Generation errors are not cached as empty sitemaps.
- Social cover endpoints read game detail without triggering recommendations.
- New migration revokes direct catalogue SELECT from PUBLIC, anon and
  authenticated, retaining service-role reads and all rows/RLS policies.
  This is prepared, not applied; live effective grants and RPC/view paths must
  still be checked after restore.
- Nginx preparation adds catalogue/API rate limits, rejects observed bulk-crawler
  identities, and writes dedicated JSON vhost logs. No trusted UA bypass. Robots
  adds search/filter exclusions and the same bulk-crawler disallows.
- Optional response-byte telemetry captures DB endpoint, method, status, duration
  and time without keys/filters/bodies. `scripts/egress-report.mjs` normalizes an
  explicitly supplied time window and keeps HTTP traffic separate from DB bytes.

## Validation and limits

Node 24.21.0 matches the repository's supported major version. Typecheck, lint,
full tests, production build and bundle budget checks run locally. See the final
check record in `validation.json` for counts. Production build uses the existing
explicit prebuild fallback flag; this is not a live database test.

`local-cache-probe.json`: Next.js 16.2.12 standalone + synthetic localhost
Supabase HTTP fixture. Repeated search API, search page, game detail, missing game
and game sitemap each made zero DB calls on the second request. Game route
reported MISS then HIT. Missing game carries Next's 404/noindex marker; streamed
HTML can have HTTP 200. Shared shell/comments may already be warm on the first
request; recorded first-call counts are not universal cold-cache totals. Payload
sizes here are fixture values, not production catalogue sizes.

`local-query-plans.txt`: isolated PostgreSQL 18, 26,000 games, 156,000 category
links, 260,000 tag links. Candidate and archive plans used indexes, one loop and
no temp spill: ~0.528 ms category, ~0.487 ms tags, ~0.021 ms archive on this local
fixture. Supabase uses PostgreSQL 17 and actual skew may differ. SELECT permission
fixture confirmed anon=false, authenticated=false, service_role=true. No live
advisors, migration application or actual Data API authorization test was possible.

Production host's Nginx successfully validated the proposed files using an
isolated `/tmp` config (`nginx -t`); active config was not changed. No promises of
80–90% measured savings or 3 GB/month compliance are made until the runbook is
completed. Authenticated live UI and post-deploy counters remain required.

Follow `docs/egress.md` for the explicit rollout and verification procedure.
